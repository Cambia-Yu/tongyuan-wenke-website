从 DeepSeek Harness 看企业 AI 转型的下一阶段

DeepSeek Harness 让模型周围那一层运行环境变得更容易被看见。进入企业以后，这个问题最终会落到工作本身：模型怎样接住前面的任务，又怎样把结果送回后面的流程。

Cambia2026.08.18
本文结构 模型之外的分工 当系统开始调度人 软件参与范围 AI 项目的变化 第三张地图 从 Harness 回到企业

DeepSeek 开源 Harness 以后，很多讨论首先落在 Agent 开发上：研究框架，捣鼓插件...这些当然是它最直接的用途。对企业来说，我更关心另外一层变化。

过去几年，企业很容易把一个 AI 系统的能力归结到模型上，模型越强，应用似乎就应该越强。而 Harness 则把模型周围那部分拆得很明白。

这可能会改变企业 AI 转型的重心。模型仍然重要，但企业下一阶段拉开差距的地方，会越来越多地落在模型怎样进入真实工作。

下面的判断主要基于公开的技术资料和企业实践。现在谈“新的企业范式”还早，但一些过去分散的变化已经可以放到一起观察。

01 · HARNESS

模型之外，正在长出一层新的分工

DeepSeek Harness 有一个很明确的架构选择。它把模型适配、工具和 Agent 的运行方式都做成了可以替换的插件，甚至连驱动 Agent 工作的循环也没有固定在核心里。DeepSeek 自己把这套思路概括成一句很简单的话：Everything is a plugin。

从开发者的角度看，这是一次很彻底的模块化；而从产业分工来看，它传递的信息更具体。模型公司可以继续提高基础能力，另一批团队开始研究怎样让模型稳定地完成更长的任务。行业开发者也有了相对独立的位置，可以把自己的专业能力接进这套运行环境。

Anthropic 最近的工程实践提供了一个很好的旁证。他们在研究长时间运行的 Agent 时发现，模型没有变化，仅仅调整 Harness 的设计，最终表现也会发生明显变化。Anthropic 因此把 Agent 的效果理解为模型和 Harness 共同作用的结果。

这对企业有一个很现实的含义。基础模型更新得很快，一家公司不可能跟着模型版本反复重做自己的业务。更适合长期积累的，是企业自己的工作方式。

德国汽车与工业供应商舍弗勒的实践很能说明这个问题。2025 年，它们和亚马逊合作，把生成式 AI 用到了汽车软件测试。模型已经能够帮助生成测试内容，但工程师仍然需要花不少时间整理需求和处理结果。后来的改造继续进入舍弗勒原有的工程工作台，让 AI 参与一套持续运行的测试工作。按照舍弗勒提供的数据，837 条系统需求对应的测试准备工时从 820 小时降到了 265 小时。

这个案例的价值在于，它把模型能力和生产能力之间的距离展示得很具体：模型能执行一个动作只解决了部分问题。进入真实生产以后，企业还需要处理模型怎样接住前面的工作，以及它产生的结果怎样回到后面的流程。

02 · HUMAN TASK

当系统开始调度人

沿着这套分工继续往企业里走，人也会进入系统的运行过程。

一项任务做到某个位置，模型可能缺少判断依据。系统把当前情况整理好，交给负责这件事的人。人给出结论以后，任务继续。从系统的角度看，这个人为提供了模型在当前情况暂时缺少的能力。

这种设计并不新。企业流程软件十多年前已经有专门的 Human Task 标准，让工作流可以把任务交给人，再等待结果返回。 所以我不太愿意把“Human is a plugin”包装成一个新概念。它更适合用来重新观察今天的企业工作。

企业已经用了很多年的 ERP 和各类业务系统，获取信息有时并不难，但麻烦经常发生在出现意外以后。因此，系统知道发生了什么，人需要理解接下来该怎么办。这一段工作长期依赖员工经验，也很难完整留在软件里。

举个例子：最近一期《AI 炼金术》采访了艾语智能创始人张天乐。艾语智能做小额债务处理，按常见思路，很容易把 AI 用在自动打电话上。他们最后选择了另一条路线，让机器根据案件情况给一线员工安排任务。张天乐在节目里把它概括为“AI 给人下任务”。

这个选择值得注意，因为此时调整的不只是一个动作。过去由专业人员自己理解情况、安排工作的部分，开始有一部分进入系统；而员工拿到的是经过整理之后更明确的任务。张天乐还提到，为了让这套方式运转，公司花了几周重新整理数据库，并把行业经验沉淀到文档和 Skill 里。

这和舍弗勒发生在不同的行业，两家公司也不能代表整个市场。但它们放在一起，会看到一个相似的问题：AI 一旦进入日常工作，企业很快会碰到原来的工作结构。只提高模型能力，很难绕开这一层。

03 · SOFTWARE

Agent 正在扩大软件能够参与的工作范围

讲到这里，很容易觉得 Agent 正在发明一种全新的工作方式。企业软件的发展历史提醒我们谨慎一点。

十多年前，流程管理领域已经专门研究过那些无法提前完整写好的工作。比如保险理赔或发票差异，现场情况会不断变化，软件可以保存当前材料，再由有经验的员工决定下一步。2014 年发布的国际 Case Management 标准 CMMN，就把这类工作作为主要对象。

所以，动态安排工作并不新，人参与流程也不新。今天这一轮 AI 的增量要放在另一个位置理解。

过去的软件很擅长处理已经能够表达清楚的规则。遇到需要理解语义的情况以后，工作经常会重新回到人手里。比如合同出现一段特殊约定，系统可以找到合同，也知道任务还没有结束，但怎样理解这段内容通常依赖业务经验。

大模型开始进入的恰好是这一段。它可以直接阅读过去难以转成规则的材料，并参与一些原本只能交给人的判断。今天的可靠性还不足以让企业完全放手，但软件能够参与的工作范围已经比传统流程系统更宽。

今年一些企业流程研究开始把这类变化放回原有工作流里讨论。研究者使用“从自动化向有限自主执行延伸”来描述它。既：流程仍然提供边界，Agent 在边界内根据当前情况做判断。

这段历史让 Agent 在企业中的位置更清楚了。企业没有必要重新发明已经运行良好的流程系统。AI 更适合进入那些过去需要人理解现场才能继续推进的地方。

这一点也解释了为什么很多企业已经上了大量软件，员工仍然觉得工作很重。在 AI 时代中，系统去承担记录和确定性流程，人在中间补充上下文。随着大模型能力提高，这部分工作开始有机会重新分配。

04 · ENTERPRISE AI

企业 AI 项目会因此发生一点变化

过去几年，做企业 AI 最常见的起点是“找场景”。有内部资料，就做知识库；客服工作量大，就考虑客服 Agent。这种方法仍然有用，只是它越来越容易碰到一个上限：场景名称一般不能告诉我们一项工作究竟怎样完成。

同一个“合同审核”场景，背后可能有完全不同的工作方式。有些公司已经有比较成熟的合同系统，AI 只需要处理少量特殊情况；另外一些公司大量信息仍然依赖员工临时整理。两家公司买同一个 Agent，最后得到的结果很可能完全不同。

所以企业 AI 服务会逐渐往前多走一步。开始做技术方案以前，需要先看清楚这项工作现在怎样运行。模型适合进入哪一段，往往要从这里判断。

这也会影响我们对“数字员工”的理解。按照岗位做一个销售 Agent 或采购 Agent，很容易形成产品概念，但企业工作并不总是按照岗位边界发生。一件事情往往会穿过已有系统，也会经过不同的人。沿着岗位复制一个 AI 角色，有时会把原来的工作结构一起复制下来。

对大型企业来说，已有软件仍然会长期存在。财务系统承担正式记录，确定性的业务规则也更适合继续交给传统程序。Agent 增加的是一种新的参与方式，让软件能够处理更多过去依赖人理解的工作。

企业主越来越应该关注的，并不是企业内还能做多少个 Agent，而是一项工作里还有多少内容只存在于员工经验中。

这些地方往往决定了 AI 能不能从 Demo 继续走向生产。

05 · EXECUTION MAP

企业可能还缺一种对工作的表示

Palantir 在这一点上提供了一个很有参考价值的行业样本。

Palantir 长期为政府和大型企业处理复杂运营问题。它的产品里有一层叫 Ontology，可以简单理解为企业业务在软件中的一套表示。系统看到的不只是数据库里的记录，还知道这些记录对应什么业务对象，以及围绕它们允许发生什么动作。今天 Palantir 已经把这层能力用于 AI Agent，让人和 Agent 基于同一套企业业务关系工作。

Palantir 的方案当然不能直接变成所有企业的答案。它有价值的地方在于提出了一个长期问题：如果 AI 要参与企业工作，仅仅接入数据是不够的。它还需要理解这些数据在公司里意味着什么。

企业今天已经很习惯用组织架构图描述人，用 IT 架构图描述系统。工作本身的运行方式则经常散落在制度和人的经验里。Agent 开始参与执行以后，这部分信息会越来越难继续保持隐形。

我们可以暂时把未来可能出现的这种表示叫作“执行地图”。它描述的是一项工作如何向前推进，以及 AI 能够参与到什么程度。企业最终需要解决的，只是把原本依赖员工自然理解的那部分工作，逐渐变成机器也能够理解的结构。

06 · RETURN

从 Harness 再回到企业

回过头看 DeepSeek Harness，它本身仍然是一套快速演进中的开发基础设施。今天最成熟的长时间 Agent 实践也主要集中在软件开发，距离很多复杂企业业务还有相当长的路。

所以，现在没有必要把 Harness 描述成企业软件的下一代形态。它提供的价值更像一个观察窗口：当模型开始获得持续行动能力以后，模型周围的运行环境会越来越重要；进入企业以后，这个问题又会进一步落到工作本身。

舍弗勒遇到的是工程工作台的问题，艾语智能开始调整机器和员工之间的任务关系，Palantir则长期在建设机器能够理解的企业业务表示。 这些实践虽然所处阶段不同，但都说明 AI 深入企业以后，项目很难长期停留在模型这一层。

未来企业 AI 的核心资产，很可能会越来越少地体现在“用了什么模型”，更多地体现在一家公司能否把自己的工作方式整理成机器可以参与的系统。

现有软件会继续承担正式业务，人也会长期保留需要经验和组织责任的判断。变化发生在两者之间。过去依赖员工自然协调的部分工作，开始有机会进入软件。

这会逐渐改变企业 AI 项目的竞争方式。模型能力越来越容易获得以后，对业务本身的理解会重新变得昂贵。谁知道一项工作究竟怎样运行，知道 AI 应该进入哪里，也能够把这些判断落实到系统里，谁就更容易把这一轮模型进步变成长期能力。

对于企业服务公司，我认为这里会形成一条比“做更多 Agent”更值得积累的路线：理解企业怎样完成工作，并把其中适合机器参与的部分逐渐沉淀下来。

DeepSeek Harness 让这条路线更容易被看见。

但至于它最后会不会发展成一次足够大的企业 AI 范式变化，现在还需要更多企业实践来回答。
